# Conformance Test Vector Schema

This document defines the language-neutral schema for conformance golden vectors.
Future implementations (e.g. loops-go) can prove semantic equivalence with the reference implementation by replaying these vectors.

---

## 1. Vector Envelope

Every vector file is a single JSON document located at:
`spec/conformance/vectors/<area>/<name>.json`

### Envelope Fields

| Field | Type | Required | Description |
|---|---|---|---|
| `name` | string | Yes | Short kebab-case identifier matching the file stem (e.g. `fold-key-string-projection-merge`). |
| `description` | string | Yes | One sentence: what semantic decision this pins and why it exists. Must mention relevant decision tags when applicable. |
| `input` | object | Yes | Area-specific input parameters. |
| `expected` | object \| array \| primitive | Yes | The exact expected output after executing the input on the system under test. |

### Envelope Example

```json
{
  "name": "example-vector",
  "description": "Pins a specific edge semantic under replay.",
  "input": {
    "spec": { ... },
    "payloads": [ ... ]
  },
  "expected": { ... }
}
```

## 2. Area: `fold`

The `fold` area pins the execution semantics of `atoms.Spec.replay`: given a Spec definition and an ordered sequence of fact payloads, it produces the exact accumulated final state.

### `input` Schema

| Field | Type | Required | Description |
|---|---|---|---|
| `spec` | Spec Object | Yes | The spec definition defining state fields and fold operations. |
| `payloads` | array of objects | Yes | Ordered sequence of event payload dictionaries to replay. Payloads may include `_ts`, `ref`, and arbitrary application fields. |

### `expected` Schema

An object representing the final state dictionary. Every key in the dictionary corresponds to either a declared `state_fields` target, an auxiliary state key generated by a fold operation (e.g., `{target}_sum`, `{target}_count` for `avg`), or an error-rejection counter (e.g., `{target}_rejected`).

---

## 3. Spec Encoding

A `Spec` defines data contracts and fold rules.

### Spec Object

| Field | Type | Required | Description |
|---|---|---|---|
| `name` | string | Yes | Unique identifier for the spec. |
| `about` | string | No | Human-readable description (default: `""`). |
| `input_fields` | array of Field Objects | No | Input field declarations (default: `[]`). |
| `state_fields` | array of Field Objects | Yes | State field declarations. |
| `folds` | array of FoldOp Objects | Yes | Ordered fold transformations to apply to incoming payloads. |

### Field Object

| Field | Type | Required | Description |
|---|---|---|---|
| `name` | string | Yes | Field identifier. |
| `kind` | string | Yes | Type name: `"str"`, `"int"`, `"float"`, `"bool"`, `"dict"`, `"list"`, `"set"`, `"datetime"`. |
| `optional` | boolean | No | Whether the field may be absent (default: `false`). |

---

## 4. Fold Operations (`FoldOp`)

Each fold operation is a JSON object with a discriminator field `"op"`.

### `latest`
Stores the timestamp `_ts` of the latest event. If `_ts` is missing or `null`, the payload is rejected and increments `{target}_rejected` (decision: `fold-off-type-skip-with-counter`).

```json
{
  "op": "latest",
  "target": "last_seen"
}
```

### `count`
Increments an integer counter in `{target}` on every payload.

```json
{
  "op": "count",
  "target": "events"
}
```

### `sum`
Adds numeric `payload[field]` to `{target}`.
- If `field` is absent / `null`: silently skipped.
- If `field` value is non-numeric or boolean: skipped, increments `{target}_rejected`.

```json
{
  "op": "sum",
  "target": "total",
  "field": "amount"
}
```

### `collect`
Appends incoming payload to `{target}` (list).
- If `ref` field is present on payload, it is parsed (comma-separated, whitespace-trimmed) into sorted unique `_refs` array on the stored entry.
- If `max` > 0 and list length exceeds `max`, oldest items are dropped (bounded buffer).

```json
{
  "op": "collect",
  "target": "history",
  "max": 100
}
```

### `upsert`
Inserts or updates an entry in `{target}` (dict) keyed by `payload[key]`.
- **String projection** (`decision:design/fold-key-string-projection`): The key is projected using `str(payload[key])`.
- **Null key**: If `payload[key]` is `null` or missing, the payload is skipped.
- **Merge default** (`decision:design/fold-merge-default`): New fields overlay existing entry fields; unmentioned prior fields persist.
- **Observation count `_n`**: Incremented on each upsert for the key.
- **Ref accumulation**: If `ref` is present on payload, comma-separated tokens are accumulated into `_refs` (sorted list of unique tokens across all upserts for this key).

```json
{
  "op": "upsert",
  "target": "users",
  "key": "id"
}
```

### `top_n`
Maintains a dictionary in `{target}` with top `n` items ranked by numeric `by` field, keyed by `payload[key]`.
- Key is string-projected (`str(key)`).
- If `key` or `by` is absent / `null`: silently skipped.
- If `by` is off-type (non-numeric / bool): skipped, increments `{target}_rejected`.
- Ties preserve insertion order under stable sort.

```json
{
  "op": "top_n",
  "target": "leaderboard",
  "key": "player",
  "by": "score",
  "n": 10,
  "desc": true
}
```

### `min`
Tracks minimum numeric value in `{target}`.
- Replaces initial `null` with first valid number.
- Non-numeric / boolean values increment `{target}_rejected`.
- Missing fields are silently skipped.

```json
{
  "op": "min",
  "target": "coldest",
  "field": "temp"
}
```

### `max`
Tracks maximum numeric value in `{target}`.
- Replaces initial `null` with first valid number.
- Non-numeric / boolean values increment `{target}_rejected`.
- Missing fields are silently skipped.

```json
{
  "op": "max",
  "target": "warmest",
  "field": "temp"
}
```

### `avg`
Tracks incremental running average in `{target}`.
- Maintains hidden state keys `{target}_sum` (float) and `{target}_count` (int).
- Off-type values increment `{target}_rejected` and do not bump `{target}_count`.
- Missing fields are silently skipped.

```json
{
  "op": "avg",
  "target": "mean_latency",
  "field": "latency"
}
```

### `window`
Sliding FIFO window of field values in `{target}` (list).
- Appends `payload[field]` to list.
- If list length exceeds `size`, oldest values are dropped.
- Missing fields are silently skipped.

```json
{
  "op": "window",
  "target": "recent_intervals",
  "field": "interval",
  "size": 10
}
```

## 5. Fact Encoding

A `Fact` is an intentional observation with a routing kind, timestamp, payload, observer, and origin. In `replay` and `witness` vectors, facts are provided in append order as `[fact_id, Fact Object]` pairs.

### `[fact_id, Fact Object]` Pair

A 2-element JSON array: `[string, object]`
- Index 0: `fact_id` (string) — 26-character canonical identifier (e.g. Crockford ULID).
- Index 1: Fact Object (object) — serialized representation of the fact.

### Fact Object

| Field | Type | Required | Description |
|---|---|---|---|
| `kind` | string | Yes | Routing key matching the target spec (e.g. `"decision"`, `"item"`). |
| `ts` | float | Yes | Unix epoch timestamp in seconds. Sub-millisecond precision is preserved. |
| `payload` | object | Yes | Domain application payload dictionary. |
| `observer` | string | No | Identifier of the producing observer (default: `""`). |
| `origin` | string | No | Origin loop or vertex identifier (default: `""`). |

---

## 6. Area: `replay`

The `replay` area pins store-level total replay ordering and tie-breaking semantics on top of pure Spec folds.
Given an append-ordered sequence of stored facts (which assign internal receipt ordinals / rowids), a conforming store replays facts filtered by kind strictly ordered by `(ts ASC, id ASC)`. Each fact payload is augmented with system metadata fields (`_ts`, `_id`, `_observer`, `_origin`) and folded into the spec.

### `input` Schema

| Field | Type | Required | Description |
|---|---|---|---|
| `spec` | Spec Object | Yes | The spec definition defining state fields and fold operations. |
| `facts` | array of `[fact_id, Fact Object]` | Yes | Sequence of facts in APPEND order (store insertion order). |

### `expected` Schema

An object representing the final accumulated state dictionary after full replay in `(ts ASC, id ASC)` order.

---

## 7. Area: `witness`

The `witness` area pins temporal witness cursor prefix isolation (SPEC §9.3).
A witness position denotes an inclusive prefix of rows received by the store: `rowid <= cursor_rowid`. The selected prefix is replayed in `(ts ASC, id ASC)` order through the spec. Late-arriving or backdated facts appended after a witness position cannot alter the fold state observed at that position.

### `input` Schema

| Field | Type | Required | Description |
|---|---|---|---|
| `spec` | Spec Object | Yes | The spec definition defining state fields and fold operations. |
| `facts` | array of `[fact_id, Fact Object]` | Yes | Sequence of facts in APPEND order (store insertion order). |
| `cursors` | object | Yes | Key-value mapping of cursor labels to cursor addresses. |

#### Cursor Addresses

| Address Form | Description |
|---|---|
| `""` | Genesis sentinel: the empty / start-of-store position (`rowid <= 0`). Yields initial spec state. |
| `"head"` | Store head: newest row currently received in the store (`rowid <= max_rowid`). |
| `"<fact_id>"` | Canonical fact ID: point lookup resolving to the exact receipt rowid of that fact. |

### `expected` Schema

An object mapping each cursor label defined in `input.cursors` to its exact expected fold state dictionary evaluated at that witness position.
