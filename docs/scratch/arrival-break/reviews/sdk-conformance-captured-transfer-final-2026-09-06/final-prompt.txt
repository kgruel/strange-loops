===== libs/sdk/README.md =====
1: # sdk — Loops Apex Composition Library
2: 
3: `sdk` is the headless composition layer uniting `engine`, `custody`, `lang`, `store`, `atoms`, and `sign` into unified, typed operations. It serves as the single foundation for presentation layers (`apps/loops`, TUI, external agents, Python scripts) without leaking presentation logic into the core substrate.
4: 
5: ---
6: 
7: ## Architectural Guarantees
8: 
9: - **Zero Presentation Logic**: Returns pure typed dataclasses; never formats terminal escape codes or parses CLI flags.
10: - **Descriptor-First Arrival Reads**: An explicitly declared backend and instance role select the adapter; store locations remain opaque to the SDK.
11: - **Visible Legacy Boundary**: Bare `.jsonl`/SQLite inputs remain transitional and every read result labels its path as `legacy` with `basis=None`.
12: - **Witness-Axis Honesty**: Fact listing and pagination use append-order cursors (`WitnessPosition`) ensuring deterministic, non-lossy walks.
13: - **Declared Admission & Attestation**: Fact emission enforces declared observer and kind admission policies, signing with operation-fresh custody keys.
14: - **AST-Verified Ceremonies**: Declarative vertex modifications are verified against the language grammar and executed via transactional plan/apply ceremonies.
15: 
16: ---
17: 
18: ## API Reference
19: 
20: ### 1. Target Resolution & Discovery
21: 
22: ```python
23: from sdk import resolve_arrival_target, resolve_target, discover_targets, TargetInfo
24: 
25: # Supported Arrival target: the descriptor carries backend, opaque location,
26: # optional lineage pin, and mandatory instance role.
27: arrival = resolve_arrival_target("path/to/target.vertex")
28: # -> ArrivalTarget(store=StoreDescriptorInfo(backend='file', location='...', role='replica'))
29: 
30: # Single target probe
31: info = resolve_target("path/to/target.vertex")
32: # -> TargetInfo(target_type='vertex', canonical_mode='sqlite', canonical_path=..., index_path=..., exists=True, ...)
33: 
34: # Multi-target workspace discovery
35: targets = discover_targets(".", recursive=True)
36: ```
37: 
38: - **`resolve_target(target: Path | str) -> TargetInfo`**:
39:   Transitional filesystem probe for legacy targets. Raises `TargetNotFound` or `TargetUnsupported`.
40: - **`resolve_arrival_target(target: Path | str) -> ArrivalTarget`**:
41:   Parses an explicit vertex descriptor without probing or normalizing its backend-owned location. It refuses suffix inference and an omitted instance role.
42: - **`discover_targets(root_path=".", *, recursive=True, include_bare=True) -> list[TargetInfo]`**:
43:   Discovers all Loops vertices and bare stores in a directory tree.

47: ### 2. Read Operations
48: 
49: ```python
50: from sdk import (
51:     read_summary,
52:     read_facts,
53:     read_state,
54:     read_ticks,
55:     read_fact_by_id,
56:     search_facts,
57:     resolve_entity,
58:     read_timeline,
59:     sync_target,
60: )
61: 
62: # Target statistical summary & kind inventory
63: summary = read_summary("target.vertex")
64: # -> ReadSummary(read_path='arrival', basis=ReadBasis(...), store=StoreDescriptorInfo(...), ...)
65: 
66: # Bounded, cursor-bearing fact pagination
67: page = read_facts("target.vertex", limit=10, order="newest")
68: # -> FactPageResult(items=[...], next_cursor=..., truncated=True, order='newest')
69: 
70: # Arrival continuations are process-local capabilities. Pass next_cursor back
71: # to read_facts() directly; as_dict() reports has_continuation=True and redacts
72: # the engine value instead of emitting an unprotected wire token.
73: 
74: # Folded vertex state
75: state = read_state("target.vertex", kind="note")
76: # -> FoldStateResult(vertex_name='target', sections={'note': {'count': 10, 'items': [...]}})
77: 
78: # Full-text search across observation payloads
79: search_res = search_facts("target.vertex", query="refactor auth", limit=10)
80: # -> SearchResult(query='refactor auth', matches=[...], total_matches=1)
81: 
82: # Domain entity fold-key resolution
83: fact_id = resolve_entity("target.vertex", kind="task", key="task_id", value="T-100")
84: 
85: # Interleaved chronological timeline (facts + ticks)
86: timeline = read_timeline("target.vertex", limit=50)
87: 
88: # Explicit projection synchronization. Arrival sync first attests custody and
89: # catches a missing or behind projection up through the captured head.
90: sync_res = sync_target("target.vertex")
91: # -> SyncResult(read_path='arrival', captured_head=..., target=...,
92: #               projected_before=..., projected_after=..., changed=True, ...)
93: 
94: # Tick records
95: ticks = read_ticks("target.vertex", name="default")
96: for tick in ticks.items:
97:     print(tick["name"])
98: 
99: # Fact lookup by full ID or prefix
100: lookup = read_fact_by_id("target.vertex", "01M01...")
101: fact = lookup.fact
102: ```
103: 
104: `read_summary`, `read_facts`, `read_state`, `read_ticks`, and
105: `read_fact_by_id` always return typed result models. Descriptor-first results
106: carry the custody head and represented projection prefix in `basis`; legacy
107: results carry `read_path="legacy"` and `basis=None`. Descriptor reads require a
108: current projection and never materialize, repair, or catch it up. Search,
109: entity resolution, and timelines carry the same captured basis. Aggregate
110: state, summary and timeline results retain per-occurrence member bases rather
111: than inventing one shared head. `sync_target` is the
112: explicit maintenance boundary: it may catch up a missing or behind Arrival
113: projection, while inconsistent existing state and rebuild requests refuse.
114: 
115: Arrival read operations, including `resolve_entity`, `read_timeline`, and
116: `inspect_declaration`, accept an optional keyword-only `registry=` for custom
117: `engine.arrival_registry.BackendRegistry` instances. Omission selects the
118: built-in backends. A supplied registry handles every supported root and member
119: Arrival open; unknown backends refuse without fallback, and non-file locations reach
120: the named adapter unchanged. Timeline reuses its captured root when the
121: effective declaration selects aggregation. Entity resolution and declaration
122: inspection retain their current Arrival aggregate restrictions.
123: Legacy targets keep their existing behavior and do not consult the registry.
124: 
125: `export_target("target.vertex", "snapshot.jsonl")` writes an exact captured
126: wire prefix and returns its manifest, selected/captured heads and byte count.
127: `result.head` names the selected export prefix, while `result.captured_head`
128: records the source head observed when export opened; they differ for a
129: requested historical prefix. It refuses to replace an existing output. A late
130: source failure publishes no partial artifact; a directory-sync failure after
131: publication raises `ExportPublicationError` with `published=True` and the
132: complete artifact's identity. Export requires no current query projection.
133: 
134: Portable artifact import into an empty receiver remains separate.
135: `restore_forward` is a live replication operation: it opens explicit source
136: and receiver descriptors, rather than consuming an export artifact. Its
137: receiver must already be an exact source prefix. A selected historical prefix
138: below the locally witnessed source head refuses with `HeadRollback` before any
139: receiver append. Restore leaves the receiver projection unchanged; use
140: `sync_target` before a projection-backed read.

144: ### 3. Fact Emission
145: 
146: ```python
147: from sdk import BatchEmitResult, EmitReceipt, emit_batch, emit_fact, preview_emission
148: from atoms import Fact
149: 
150: # Emitting by kind and payload
151: receipt = emit_fact(
152:     "target.vertex",
153:     kind_or_fact="note",
154:     payload={"title": "Meeting Notes", "body": "Discussed SDK API"},
155:     observer="alice",
156: )
157: # Descriptor-first Arrival receipts carry the captured head, durable Commit,
158: # witness state, and post-commit projection status.
159: 
160: # Or preflight dry-run simulation
161: preview = preview_emission("target.vertex", "note", {"title": "Test"}, observer="alice")
162: 
163: # A descriptor-first batch is planned from one snapshot and uses one append.
164: batch = emit_batch(
165:     "target.vertex",
166:     [fact, ("note", {"title": "Batch item"})],
167:     observer="alice",
168: )
169: for receipt in batch.items:
170:     print(receipt.id, receipt.stored)
171: print(batch.commit, batch.atomicity, batch.projection)
172: ```
173: 
174: - **`emit_fact(target, kind_or_fact, payload=None, *, observer=None, origin="", ts=None, id_override=None, credentials=None, admit_undeclared=False, dry_run=False, registry=None) -> EmitReceipt`**:
175:   Emits a fact (or `Fact` atom) under declared admission rules. Descriptor-first Arrival writes prepare from one CURRENT snapshot, append once against its captured full head, witness the commit, then explicitly synchronize the projection. Bypassing strict kind admission requires `admit_undeclared=True`. Deterministic IDs can be specified with `id_override`. `dry_run=True` simulates emission without storage.
176: - **`preview_emission(target, kind_or_fact, payload=None, *, observer=None, origin="", ts=None, admit_undeclared=False, credentials=None, registry=None) -> EmitPreviewResult`**:
177:   Simulates emission against declared policies, checking fold key requirements without disk side effects. Arrival policy and fold metadata come from the same bounded effective declaration used for planning; a missing projection refuses without materializing it.
178: - **`emit_batch(target, facts, *, observer=None, origin="", credentials=None, admit_undeclared=False, registry=None) -> BatchEmitResult`**:
179:   Normalizes every item before resolving the target. A descriptor-first Arrival batch derives all per-item admission decisions from one current snapshot, appends the packed records under one head comparison, witnesses one shared commit, and explicitly synchronizes the projection. Each mapping item may set its own boolean `admit_undeclared`; duplicate receipts retain `stored=False`. Empty input is an explicit zero-write result. Legacy targets return the same wrapper with `atomic=False`, `atomicity="legacy-sequential"`, and no invented shared commit; `LegacyBatchPartialFailure` retains receipts if that sequential loop stops after an observable prefix.
180: 
181: `CustodyCredentialProvider()` and `CustodyCredentialProvider(key_dir=None)` use
182: the existing custody resolver. A non-`None` `key_dir` now raises
183: `SdkValueError` during construction because directory overrides were previously
184: accepted but ignored. This applies before either Arrival or legacy operations
185: can use the provider. Callers that need another credential source can continue
186: to supply a custom `CredentialProvider`; that interface does not itself create
187: an observer mapping or register public keys.
188: 
189: For an explicit persisted namespace, use `MappedCredentialProvider` with an
190: Arrival target. Prepare the binding separately from initializing the store:
191: 
192: ```python
193: from pathlib import Path
194: from sdk import MappedCredentialProvider, init_vertex, emit_fact
195: 
196: credentials = MappedCredentialProvider(
197:     Path("/absolute/path/to/private-custody"),
198:     namespace="personal",
199:     receipt_observer="alice",  # explicit local receipt-signing selection
200: )
201: binding = credentials.create_binding("alice", token="bootstrap-alice-1")
202: init_vertex(
203:     Path("observations.vertex"), store_type="arrival", observer="alice",
204:     credentials=credentials,
205: )
206: emit_fact(
207:     Path("observations.vertex"), "item", {"value": 1},
208:     observer="alice", credentials=credentials,
209: )
210: ```
211: 
212: Mapped selection uses the exact namespace and observer, independently of the
213: vertex filename or lineage. The engine checks author keys against verified
214: history through captured H, for use after H, and verifies each signature in its
215: own domain. Receipt signing uses the explicitly selected local observer and
216: the effective declaration's current receipt-key policy; the unsigned outer tick
217: still names the physical genesis custodian. Omitting `receipt_observer` permits
218: unsigned ticks before the signed-tick era, and refuses a required signed tick.
219: A missing author binding may remain unsigned where the existing policy allows;
220: a contradictory or unauthorized binding refuses before append.
221: 
222: Mapped initialization only loads a pre-created binding. For another observer,
223: prepare its binding and pass `key=binding.public_key` to `grant_observer` with
224: the existing author's credentials. Mapped `grant_observer(key=None)` refuses
225: before creating keys. Recovery of an existing Arrival initialization intent
226: signs nothing and does not require private custody to remain available.
227: Mapped providers are supported on Arrival targets; legacy writers explicitly
228: refuse them. The default `CustodyCredentialProvider` remains unchanged.
229: 
230: The runnable [two-observer mapped workload](tests/test_arrival_mapped_workload.py)
231: shows the complete public lifecycle: create Alice and Bob bindings under one
232: persisted provider root and exact namespace; initialize with Alice; grant Bob
233: using Bob's pre-created public key; then emit with both authors. For a locator
234: move that keeps the same physical file-backed store, initialize with an
235: **absolute** `location` and move only the `.vertex` file while retaining its
236: store clause, lineage, and role. Recreate `MappedCredentialProvider` with the
237: same provider root, namespace, and receipt observer before continuing work.
238: The absolute store location keeps the same store residence, while
239: mapped key selection comes only from the provider namespace and exact observer
240: label; neither the vertex filename nor its new directory chooses a key.
241: 
242: After relocation, `verify_target(relocated_vertex)` provides a `Full`
243: verification of the captured prefix's grammar, dense ordinals, lineage, and
244: record-hash chain. It does not establish projection agreement, signature
245: authorship, key trust, or the identity of an observer across lineages. The
246: mapped workload exercises public writes with captured authorization; the
247: [mapped signing tests](tests/test_arrival_mapped_credentials.py) separately
248: verify domain-specific signatures and key-history behavior.
249: 
250: `import_legacy(vertex_path, observer, token=...)` explicitly copies a verified
251: legacy key into managed storage without changing the original. It preserves
252: flat/nested ambiguity and alias refusals. After import, locator moves do not
253: change mapped selection. No read, preview, or signer load imports or creates a
254: binding. `bind_existing_ref(observer, key_ref, expected_public_key, token=...)`
255: permits deliberate reuse of a completed managed key in another namespace;
256: equal observer labels alone never select another namespace's key.
257: See [custody binding recovery](../custody/README.md#explicit-mapped-bindings)
258: for interruption handling and filesystem scope.
259: 
260: ### Recovering an interrupted mapped declaration edit
261: 
262: An edit can raise `CommittedIncomplete` after its declaration records are
263: durable but before projection synchronization or local cache publication
264: finishes. Its public `details["intent_path"]` identifies the retained recovery
265: intent. Use it before deciding whether to retry the proposal:
266: 
267: ```python
268: from sdk import CommittedIncomplete, edit_declaration, recover_declaration
269: 
270: try:
271:     edit_declaration(vertex, proposal, observer="alice", credentials=credentials)
272: except CommittedIncomplete as outcome:
273:     recovered = recover_declaration(outcome.details["intent_path"])
274: ```
275: 
276: Recovery reconciles the exact retained suffix, synchronizes the projection,
277: and publishes the retained declaration bytes without re-signing or appending
278: the proposal again. A recovery result has no original `Commit`; its basis is
279: the original captured edit basis. Follow it with `inspect_declaration(vertex)`
280: to obtain a fresh effective-declaration/read basis, and use
281: `verify_target(vertex)` when the bounded `Full` hash-chain claim is needed.
282: The [mapped declaration recovery workload](tests/test_arrival_declaration_recovery_workload.py)
283: uses a deterministic injected `after-append` interruption beneath the public
284: SDK edit call; it is not a process-kill or crash-survival test.
285: 
286: Supported Arrival execution reserves the vertex name from its loop names.
287: Every exact name collision refuses, including passive loops, reset/carry loops,
288: and count- or event-triggered boundaries. The runtime also adds an implicit
289: `cite` loop, so a vertex named `cite` cannot execute under this restriction.
290: Runtime capture checks the historized effective declaration and expanded
291: template loop names before hydration and planning; editing only the local cache
292: cannot bypass it. New and proposed declarations check their declared loops and
293: the implicit `cite` loop. The SDK initializer also refuses the name `item`,
294: because its scaffold declares an `item` loop, before creating custody keys.
295: External template sources are expanded and checked at runtime; declaration
296: editing does not load them solely to enforce this rule.
297: 
298: This is an Arrival execution compatibility restriction. Existing histories
299: remain available through evidence reads, declaration inspection and export.
300: A collision-free declaration can be appended to correct an ambiguous current
301: declaration; prior facts and ticks retain their original names and bytes.
302: This does not establish which role an already-recorded ambiguous tick had;
303: historical boundary continuity remains a separate limitation.
304: Legacy runtime behavior and the wire format retain their existing rules.

308: ### 4. Arrival Source Execution
309: 
310: ```python
311: from sdk import run_sources
312: 
313: result = await run_sources("target.vertex", observer="alice", force=False)
314: for tier in result.tiers:
315:     print(tier.outcome, tier.commit, tier.fact_ids, tier.tick_ids)
316: ```
317: 
318: - **`await run_sources(target, *, observer, force=False, credentials=None, registry=None, collector_factory=None, dispatcher=None, evaluated_at=None) -> SourceRunResult`**:
319:   Captures a CURRENT Arrival Authority before collection, fixes cadence and dependency tiers, and commits each collected tier with one exact-head batch append plus explicit projection synchronization. The lifecycle observer is always explicit. Existing custody keys are loaded when present; the operation never creates keys.
320: 
321:   When the invocation finishes without a terminal failure, a source error returns `status="error"` with its yielded observations and error lifecycle fact durable. Interrupted results retain prior commits and distinguish `known_uncommitted` collection from an append whose durability is `unknown`; collectors are not rerun within the invocation. When `dispatcher` is omitted, captured tick run intents remain visible with `dispatch_status="not-requested"` and `attempted=False`. This operation supports explicit single-store Arrival Authority descriptors only and never falls through to legacy source execution.
322: 
323:   Coordinator failures during ID allocation, lifecycle construction, or otherwise successful collector cleanup return an incomplete result with terminal category `collection-failed`. `terminal.details.collection` contains the current tier's basis, `custody="not-attempted"`, completed siblings, and paired partial observations from failed or cancelled siblings. Incomplete attempts have no lifecycle fact; prior tiers keep their commits. These partial observations live in terminal evidence, not `known_uncommitted`, which describes a fully collected tier. Owned iterators and distinct iterable owners receive `aclose()` when available; caller cancellation propagates after sibling cleanup. Closing a collector does not undo its external effects or guarantee subprocess termination.
324: 
325:   Calling `run_sources` again is a fresh, cadence-based invocation with fresh
326:   generated IDs; it is not a resume token for retained collector output. For
327:   example, an upstream source can remain skipped by its persisted successful
328:   cadence while a downstream source retries from its persisted trigger. A
329:   downstream failure before yielding leaves no domain observation from that
330:   collector attempt to repeat; it says nothing about its external effects. If
331:   it yielded before reporting a `SourceError` and that tier has an actual
332:   commit, the observation and error lifecycle are durable. A later fresh
333:   invocation can collect the same logical observation again under a distinct
334:   fact ID. Callers need a source-specific idempotency or reconciliation policy
335:   for external effects and overlapping collected observations. The public
336:   two-tier case is exercised in
337:   [`tests/test_arrival_source_resumption_workload.py`](tests/test_arrival_source_resumption_workload.py).

417: ## Exception Taxonomy
418: 
419: ```mermaid
420: graph TD
421:     SdkError --> TargetError
422:     TargetError --> TargetNotFound
423:     TargetError --> TargetUnsupported
424:     TargetError --> TargetNotWritable
425:     SdkError --> AdmissionFailed
426:     SdkError --> EmissionFailed
427:     SdkError --> SdkValueError
428:     SdkValueError --> InvalidEmissionRequest
429:     EmissionFailed --> InvalidEmissionRequest
430:     EmissionFailed --> CommittedEmissionError
431:     SdkError --> CeremonyFailed
432: ```
433: 
434: - **`SdkError`**: Base class for all high-level SDK exceptions.
435: - **`SdkValueError`**: Base class for SDK parameter and validation errors (inherits from `ValueError`).
436: - **`TargetNotFound`**: Target path does not exist on disk.
437: - **`TargetUnsupported`**: Path exists but is not a recognized Loops artifact.
438: - **`TargetNotWritable`**: Target or derived index cannot be written to.
439: - **`AdmissionFailed`**: Declared admission policy (strict kinds or observer grants) refused the operation.
440: - **`EmissionFailed`**: Fact emission failed prior to committing.
441: - **`InvalidEmissionRequest`**: Invalid emission parameters (missing required observer or invalid shape).
442: - **`CommittedEmissionError`**: Fact was written to storage, but a post-commit task failed (carries `.fact_id`).
443: - **`CeremonyFailed`**: Declaration update AST generation or ceremony apply was refused.
444: 
445: Descriptor-first reads also surface engine contract refusals (for example, a
446: missing or behind projection or an invalid continuation) and declaration
447: resolution errors. These keep the adapter's evidence-bearing refusal intact.
448: 
449: Arrival `sync_target` and `sync_search_index` normalize maintenance failures as
450: `ProjectionOutcomeUnknown`. Their optional `details.evidence` object uses
451: `loops.sdk/evidence/v1`: it records the coordinator phase, resource effects,
452: available head/coverage coordinates, and up to two explicit causal exceptions.
453: Search failures before the build call report derived state as
454: `not-entered`/`not-attempted`; failures after entering build or projection
455: catch-up report `entered`/`unknown`. A nested refusal does not prove that an
456: adapter left derived state unchanged. Existing error outcomes, source types,
457: and operation-specific `details.phase` remain intact. Cause messages are capped
458: at 512 characters; record bodies and implicit exception context are excluded.
459: Declaration preparation refusals carry preparation evidence without claiming a
460: custody append. Cancellation and process-control exceptions propagate unchanged.

462: ## Restore an existing exact copy
463: 
464: ```python
465: from sdk import restore_forward
466: 
467: restored = restore_forward("source.vertex", "replica.vertex")
468: print(restored.before, restored.after)
469: ```
470: 
471: Both vertices require explicit Arrival descriptors. The receiver must already
472: be an exact prefix of the verified source. Restoration appends the complete
473: missing suffix atomically through at least the witnessed head, preserving its
474: declared role. `restored.commit` is an actual receipt, or `None` when the exact
475: selected head is already present. Projection catch-up remains explicit.
476: 
477: Ordinary opening still refuses rollback. `CommittedOutcomeUnknown` retains
478: before/target heads when a replication receipt was lost;
479: `CommittedIncomplete` retains the commit if later witnessing or comparison
480: failed. Empty receiver installation is a separate, pending import operation.

69:     """Publish a complete exact wire prefix exclusively at ``output``.
70:

196:     """Refuse a represented projection whose bounded rows differ from custody.
