265: def _scoped_signer_for(
266:     vertex_path: Path, domain: str
267: ) -> Callable[[str, str], str | None] | None:
268:     """Build a per-observer signer under an explicit domain."""
269:     keys_root = keys_dir_for(vertex_path)
270:     if not keys_root.exists():
271:         return None

273:
274:     self_observer = _self_observer(vertex_path)
275:     cache: dict[str, ed25519.Keypair | None] = {}
276:
277:     def _keypair(observer: str):
278:         # An empty observer must never sign: ``keys_root / ""`` collapses
279:         # to the flat layout, which would mint the VERTEX key's authorship
280:         # claim for an anonymous writer. Same guard for path traversal —
281:         # an observer name is a key, not a path expression.
282:         if observer in cache:
283:             return cache[observer]

285:             key_dir = _self_key_dir(vertex_path)
286:         else:
287:             if not _valid_key_observer(observer):
288:                 return None
289:             key_dir = _observer_key_dir(keys_root, observer)
290:         if key_dir is None:
291:             cache[observer] = None
292:             return None
293:         keypair = _load_existing_keypair(key_dir)
294:         if keypair is None:  # Deleted after selection: remain in unsigned era.
295:             cache[observer] = None
296:             return None
297:         cache[observer] = keypair
298:         return cache[observer]

300:     def signer(observer: str, digest: str) -> str | None:
301:         keypair = _keypair(observer)
302:         if keypair is None:
303:             return None
304:         return ed25519.sign(keypair, digest.encode(), domain=domain)

306:     return signer

18:
19: ## Scope
20:
21: This audit checks the SDK custody-provider boundary, all provider callsites,
22: and the relationship between local signing material, public observer
23: registration, and the Arrival signing domains. It does not change production or
24: tests.
25:
26: ## Callsite inventory
27:
28: `CustodyCredentialProvider` is public through `sdk.__init__` and is constructed
29: as the default provider by `emit.py`, `declare.py`, `kind.py`, and
30: `sources.py`. Its `for_write(vertex)` returns the three independent
31: `WriteCredentials` callables: fact, Arrival, and tick. The callables are
32: constructed by `custody.signing` from the vertex path, so they use the
33: co-located `keys/` layout and exact observer directory rules.
34:
35: The SDK write entrypoints that accept a `CredentialProvider` are
36: `emit_fact`, `emit_batch`, `preview_emission`, `add_kind`, `edit_kind`,
37: `remove_kind`, `revoke_observer`, and `run_sources`; declaration edits also
38: accept a provider or already-created `WriteCredentials`. These paths call
39: `for_write` and pass all three domains into the engine. No current caller
40: passes `key_dir` to the provider except the regression tests.
41:
42: `grant_observer` is a separate registration path. With `key=None`,
43: `kind.py:466-484` calls `custody.ensure_signing_key(vertex_path,
44: observer=observer_name)` directly, then uses the configured provider only for
45: the authoring declaration append. Thus a custom `CredentialProvider` controls
46: the declaration author's signing callables but does not control where the new
47: observer's registered public key is generated. This is a real API limitation;
48: it is safe only while registration remains explicitly co-located custody or
49: the caller supplies `key=`. A future mapped provider must cover registration
50: and all three signing domains together.
51:
52: Arrival initialization has the analogous explicit boundary: the default path
53: uses `ensure_signing_key` plus the fact and Arrival signers, while complete
54: custom initialization requires caller-supplied `signer`, `fact_signer`, and
55: `public_key` (`declare.py:505-526`). A partial custom pair is refused. This
56: keeps key publication and both signature domains matched, but there is no
57: generic `CredentialProvider` parameter for initializer key generation.
58:
59: ## C4 disposition and risks
60:
61: The accepted C4 fix makes `CustodyCredentialProvider(key_dir=...)` refuse
62: immediately with `SdkValueError` (`sdk/emit.py:95-100`) before any signer lookup
63: or filesystem operation. The paired tests cover positional and keyword forms,
64: assert no custody resolver is called, and check a missing directory stays absent
65: while an existing directory and its sentinel content remain unchanged.
66: This resolves the prior accepted-but-unused configuration hazard
67: without inventing a second key-root mapping.
68:
69: The refusal is the correct bounded behavior under the current custody contract:
70: `fact_signer_for`, `arrival_signer_for`, and `tick_signer_for` each accept a
71: vertex path, and the public key-history verifier binds exact observer labels to
72: introduced keys. Silently treating `key_dir` as a root for only one signer or
73: for registration would create domain/key mismatches. The compatibility impact
74: is that callers should use the default constructor only when the co-located
75: custody layout is intended. Callers that intended an alternate key root need an
76: explicit custom signer/provider and must arrange observer registration
77: consistently; no migration of existing co-located keys is implied.
78:
79: The remaining registration limitation is deferred API debt rather than a C4
80: regression. A custom provider plus `grant_observer(key=None)` can still mint the
81: new observer key under default co-located custody while signing the declaration
82: with custom author credentials. The public result remains cryptographically
83: coherent when the supplied `key` is intentional, but a deployment expecting
84: the provider to own all key material must pass the key explicitly or wait for a
85: provider API that accepts observer and signing-domain requests. No current
86: contract says `CredentialProvider` owns public-key generation, so this should
87: not be presented as a failed C4 guarantee.
88:
89: ## Validation status
90:
91: The source audit found no other provider callsite that interprets `key_dir` or
92: silently falls back to a legacy writer. The concrete C4 acceptance boundary is
93: the early typed refusal and no-resolution/no-filesystem side effect, followed
94: by unchanged default three-domain signing. The final full SDK and architecture
95: results above were run after the implementation freeze.
