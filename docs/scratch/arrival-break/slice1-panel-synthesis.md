**Forward costs**: THE LABEL SUB-CHOICE IS NOT ONE OPTION, IT IS THREE, and it must be pinned in the same ruling: (a) the tick's own name — today's ruled-out convention; (b) the log's own genesis observer via `self._log.genesis()['observer']` inside ArrivalStore._write — zero new plumbing, memoized, the most literal reading of 'consistent with genesis', but merge.py's `_entry_for` has no live ArrivalLog in scope and would have to open the source log a second time to get it; (c) a live vertex/operator identity — the brief's 'the vertex's own observer, e.g. project' — which is NOT reachable today: ArrivalStore.__init__ takes no custodian kwarg, open_canonical_store forwards only signer callables (compiler.py:956-962), and tick_signer_for (signing.py:75-88) returns a bare digest->sig closure carrying no identity string. ## Panel recommendation (advisory)

PANEL RECOMMENDATION (advisory only — the ruling is Kyle's, at the session): take A, with the label sub-choice pinned in the same ruling, and two companion rulings recorded explicitly: (1) tick outer signatures are DEFERRED on purpose, so wire v1 pins with ticks outer-unsigned by decision rather than by omission; (2) the batch rows[0] privileging is INHERITED under A, and should be recorded as either a documented invariant or an enforced one (see rider notes) rather than left as a silent wart. On the label, the panel's ordering is: prefer (b) the log's own genesis observer, `self._log.genesis()['observer']` — the only zero-plumbing option that is literally 'consistent with genesis' as the brief phrases the goal — over (c) a live vertex identity, which requires threading a new custodian parameter through open_canonical_store → ArrivalStore → _write and is the only reading that matches the brief's 'e.g. project' wording. If the session prefers (c) on semantic grounds, the plumbing cost should be accepted openly, not discovered at implementation. Whichever is chosen, the edit must land at BOTH mint sites (arrival_store.py:462 and merge.py:749-755) in the same change, and merge's access to (b) requires a source-log genesis read it does not do today — that is the one non-trivial cost inside A.

## Rationale

The verified constraints funnel toward A by elimination, not by enthusiasm. C's premise — 'the outer signature is a custody claim, so the envelope observer should name the custodian' — is contradicted by the implemented machinery: `fact_signer_for` resolves the AUTHOR's per-observer key by the envelope observer value, and `_resolve` verifies against that author's registry entries, so today's outer fact signature is an authorship signature. C is therefore not a relabel; it re-keys every fact and batch outer signature from author to custodian and narrows what verify_authorship establishes. That may still be the right call, but it is a different and much larger decision than 'pick a spelling for the tick observer', and it should not be made as a side effect of closing a tick seam. D as literally scoped is not self-sufficient: dropping the field leaves genesis and key introductions with no persisted identity to seed the key registry, and the genesis body is a ratified three-field shape, so D requires reopening a ratified fact — it defers the problem rather than dissolving it, while carrying the largest doc and test blast of the four. B is the cheapest-looking option but costs a kind-conditional branch in a validator that is deliberately kind-agnostic (the `_placement_fault` split is the evidence), and — the decisive point — it forecloses outer-signed ticks, because the custody signer explicitly refuses an empty observer by design. Choosing B is choosing to close the second agenda item, not defer it. A is the least-cost coherent option: no grammar change, no commitment-shape change, no re-keying of any signature, zero vector regen, and it leaves both the fact/batch semantics and the tick-signing question open for a later ruling made on its own merits. Its honest weakness is that A's claim is unverifiable while ticks are outer-unsigned — but an unverifiable true claim is strictly better than the verifiably false one on the wire today ('a name is not an authorship claim', already ruled), and the deferral is recoverable in a way that C's re-keying and D's body amendment are not. Everything here is free only until the first `.arrival` store exists; A is also the option that leaves the most doors open after that point passes.

## Rider notes

RIDER 1 — batch rows[0] privileging (arrival_store.py:526). Verified NOT a live bug today, and the reason matters: the edit ceremony assembles all its rows against ONE `observer` variable (sqlite_store.py ~1769-1813; the other `_ceremony_persist` caller at :1632 passes a single row), so `rows[0][3]` currently equals every row's observer by construction. What is missing is any enforcement or statement of that invariant at the arrival seam — `_ceremony_persist` reads row 0 without grouping, checking, or documenting uniformity. The real cost if it ever breaks is not a bad label: `signer=self._fact_signer` at :529 means row 0's author's key signs an outer commitment covering every row's content, so a multi-observer batch would have one author attesting to another's facts. Disposition per candidate: C kills it (the field stops reading any row); A and B inherit it unchanged; D hides it from the wire but rows[0] still selects the signing key, so D does not kill it either. Panel note: this is a textbook ratchet-test candidate — the invariant currently lives only in the call chain's shape, and either a same-observer assertion at the ceremony seam or an explicit docstring statement would cost almost nothing while the file is open, which is exactly what the brief's 'cheap while the file is open' framing anticipates.

RIDER 2 — should ticks gain outer signatures? Three verified facts bear on the deferral. (a) It is currently a clean non-question: `_resolve` is gated on `_SIG in record` (arrival.py:1746), every tick mint passes signer=None (arrival_store.py:465), and merge's Entry has no signer field at all — deliberately, per its docstring ('a signer here would be a parameter with no caller and an invitation to fabricate authorship'). So no tick's envelope observer is ever looked up in the key registry today, under any candidate. (b) B forecloses the option: signing.py's `_keypair` guard refuses an empty observer by design, so an empty-observer tick cannot be outer-signed without reworking custody. A and C leave the door open; D closes it differently (nothing left to key a signer selection on for ticks). (c) A makes the deferral visible rather than silent, which is a virtue: A puts a claim on the wire that is true but unverified, and the ruling should say so in those words. Panel position: defer tick signing explicitly, and record that wire v1 pins with ticks outer-unsigned ON PURPOSE — the brief already asks for this and the evidence supports granting it.

RIDER 3 (unasked, but load-bearing and the panel flags it) — THE TWO DOCS CONFLICT ON WHAT THE OUTER SIGNATURE IS, and one of them will be false whichever candidate wins. protocol.html §06 (:347-355): 'Arrival separates what an observer authored from where a custodian placed it. The optional record signature covers the content commitment... A signed fact can therefore move between custody lineages without fabricating a new author signature' — that is the outer sig as the AUTHOR's portable signature. wire-format.html's ruled-seams callout (:240-254): 'The inner fact-domain signature beside the outer arrival-content signature KEEPS — two subjects (author content, custody record)' — that is the outer sig as the CUSTODY record. The code splits the difference and both halves are verified: it is signed by the author's per-observer key (protocol.html's half — signing.py:103-150, arrival.py:1338) but minted only in the home lineage and dropped at merge, since Entry carries no signer and merged records ride with only the inner row signature carried verbatim (wire-format's half, and the task framing's 'per-lineage'). The session cannot pick a meaning for the envelope observer without implicitly picking a side here, because that field is what selects the signing key. Recommend the ruling state which half is law and mark the losing prose for rewrite in the same change — A and B leave the conflict standing (fine, if named); C and D each resolve it toward custody and make protocol.html §06 false as written.
